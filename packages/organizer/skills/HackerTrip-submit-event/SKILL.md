# 将赛事文档整理到本人草稿箱

推荐入口：主办方选择本 Skill，并附上赛事文档或资料，例如：

```text
@hackertrip-submit-event
请根据附件整理赛事信息。不确定的内容请用选择题问我，确认后保存到我的 HackerTrip 草稿箱。
[附赛事文档、官网链接或海报]
```

`@` 是支持技能提及的 Agent 中的交互示例；实际使用宿主提供的技能选择方式。CLI 是本 Skill 调用的执行工具，主办方不需要手写 JSON 或逐条运行命令。

## 分析资料和信息完整度

先阅读用户已提供的文档、附件和链接，提取字段及对应来源；支持视觉输入的 Agent 可识别海报，CLI 本身不做 OCR。不能读取附件或访问链接时，说明具体缺口，请用户粘贴相关段落或提供可读资料，不声称已经读过。

将信息区分为「资料明确」「待主办方确认」「尚未提供」。同一字段有冲突时展示冲突值与各自出处；不要默默选一个。不要把推断写成已确认事实，不编造日期、奖金、联系方式、权限或图片链接。

按两个层次检查：

- **保存草稿必需**：`name`、`city`、`startDate`、`endDate`、`website`，以及有效主办方凭证。日期必须是真实的 YYYY-MM-DD，开始不晚于结束，网址须为 http(s)。缺官网时可提出使用资料中的正式报名页作为入口链接，由主办方确认；不能填虚构或占位网址。线上活动的城市填写「线上」。
- **后续平台审核需要核对**：举办形式、线下地址（线下/混合）、报名开始/截止日期与具体时刻、活动开始/结束时刻、介绍、赛道、奖金/资源、主办方联系方式、封面与列表封面、报名方式及对应入口。按品类和举办形式判断适用项，不把所有选填字段都变成阻塞项。CLI 不会自动上传电脑里的封面文件。

`category` 仅为 `hackathon` 或 `incubator`；孵化项目须有对应频道权限。AI 福利回小程序人工填写；不要把其他活动擅自改称黑客松。

## 用选择题补齐和确认

围绕影响保存、准确性或后续审核的缺口集中提问，避免逐字段机械追问。文档已经明确的信息不再重复询问。优先使用宿主的结构化提问/选择工具；没有该工具时用编号选项，允许主办方输入自己的答案。

选项只包含资料支持的候选值或明确的处理方式；有推荐项时说明依据。推荐或预选不等于用户已回答，不因等待超时而擅自确认。

例如：

- 「文档写了两种举办形式，请确认：① 线下，地点为文档中的上海地址；② 线上；③ 混合。」仅在资料确实支持这些候选时列出；否则直接询问举办形式，不虚构候选地点。
- 「海报是 11 月 8–9 日，正文是 11 月 15–16 日，以哪一个为准？① 海报；② 正文；③ 我提供新日期。」缺少年份时也要确认年份。
- 「报名截止时间未提供：① 现在补充；② 暂不填写，先存草稿，回小程序补齐。」不要擅自采用开赛时间或 23:59。
- 「介绍和封面暂缺：① 现在补充资料；② 根据已提供的事实整理介绍，封面回小程序补齐；③ 先存现有草稿。」基于事实生成的介绍须在摘要中标明为 Agent 整理。

草稿必需字段缺失或有关键冲突时，等待用户回答后再执行。非必填项暂缺时，说明这会影响后续提审，让主办方选择继续补齐或先存草稿；保留缺项，不编造补全，不反复阻止用户先存草稿。

可选字段包括 `techStack`、`tags`、`agenda`（date/time/title）、`live`。时刻为 HH:mm；文档有其他时区时说明转换到北京时间，时区不明且会影响时间含义时先确认。仅在主办方明确申请并同意授权时填写官方转播申请字段，不默认勾选授权、不填写官方转播结果、feedId、nonceId 或回放 ID。

## 凭证与上传前摘要

缺少凭证时引导：HackerTrip 小程序 → 我的 → 我要举办 → 主办方认证（未认证先申请）→ 发起赛事&项目 / 发布黑客松 → 让 AI 帮我提交 → 复制指令给自己的 Agent。

只在该主办方自己的电脑端使用编号和密钥。不打印密钥、不写入赛事 JSON、文档或 Git，不发送到群聊。禁止猜测凭证、账号归属或频道权限；凭证外泄时从原页面重置。

上传前用一段简短摘要展示：赛事名称、品类、举办形式/城市、起止日期、入口链接、已确认的关键选择和仍待补项。明确写出「本次仅保存到本人草稿箱，状态为待提交，不会提交平台审核」。

用户最初已明确授权保存，且关键不确定项已回答时，摘要后直接执行，无需再增加一次重复确认。用户要求先预览，或仍有未确认的必需字段/关键冲突时，停在摘要等待答复。

## 执行与回执

需要 Node.js ≥18 和能执行终端的 Agent。新流程使用配套发布的 CLI ≥1.4.1；执行前检查版本及实际后端回执，不把本地修改当成已上线。

将确认后的字段写入 `event.json`（不含凭证），通过 CLI 保存：

```bash
npx hackertrip@latest --version
npx hackertrip@latest submit-event --organizer-no <主办方编号> --submit-key <提交密钥> --from event.json
```

也支持 `HACKERTRIP_ORGANIZER_NO` / `HACKERTRIP_SUBMIT_KEY` 环境变量传凭证。默认 eventSync 地址已内置，不需要选手登录扫码或全局安装 CLI。仅在收到真实草稿 ID 且状态为 `pending_submission` 时报告保存成功；其他状态如实说明，不能自动代主办方提审。

随后用同一组凭证只读查询，核对该草稿 ID 和状态：

```bash
npx hackertrip@latest event-status --organizer-no <主办方编号> --submit-key <提交密钥>
```

完成后简短返回：草稿 ID、待提交状态、已确认的关键项、仍待补项，以及「小程序 → 我的 → 我要举办 → 赛事&项目管理 → 查看详情 → 编辑并保存 → 主办方亲自提交平台审核」。审核中可查看；审核通过并上架后归入在线赛事与项目。

网络超时或回执不明时先查询，不盲目重复上传。`submit-event` 每次新建草稿，不用于覆盖更新已有赛事；收到保存成功回执后，查询暂未读到也不能重新上传。已有草稿的编辑和后续提审回小程序完成。旧配对码参数仍兼容，日常优先编号和密钥方式。
